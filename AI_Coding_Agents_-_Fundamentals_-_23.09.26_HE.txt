נושא מרכזי: הנדסת Harness (רתמה) לסוכני קוד מבוססי בינה מלאכותית

השיעור מציג סקירה מקיפה של "הנדסת Harness" (Harness Engineering), מושג
חיוני לניהול ולשליטה יעילים בסוכני קוד מבוססי בינה מלאכותית. השיעור מדגיש
שה-"Harness" – הסביבה והתשתית הסובבת שבתוכן פועל מודל השפה (LLM) – הוא
לעיתים קרובות קריטי יותר מהמודל עצמו להצלחה בכתיבת קוד אוטונומית. המטרה
היא להעניק למפתחים את הכלים וההבנה הדרושים כדי למנף סוכני AI ביעילות,
לייעל עלויות ולהבטיח תוצרים אמינים.

מושגי מפתח ורכיבי ה-Harness:

1.  שכבות ה-Harness: ה-Harness בנוי מכמה שכבות:

    -   שכבת הליבה (מודלי LLM): הבסיס, הכולל מודלי שפה גדולים (LLMs)
        שונים כגון Haiku, Sonnet, Opus, Fable ו-Mythos.

        -   בחירת מודל: בחירת המודל המתאים תלויה במורכבות המשימה, ברמת
            החשיבה הרצויה ("מאמץ חשיבה" – thinking effort), בגודל חלון
            ההקשר (context window) ובעלות. מודלים קטנים (למשל Haiku)
            מתאימים למשימות פשוטות, בעוד שמודלים גדולים (למשל Opus,
            Fable) מצטיינים בהסקה מורכבת, אך הם יקרים יותר ועשויים להיות
            איטיים יותר.
        -   תהליך הסקה/חשיבה: מודלים מתקדמים יכולים לבצע תהליך פנימי של
            "שרשרת מחשבה" (chain of thought) לפני הפקת הפלט. תהליך זה
            צורך יותר "טוקני פלט" (output tokens), אך מוביל לפתרונות
            חכמים יותר. לרוב ניתן להגדיר את רמת "מאמץ החשיבה".

    -   שכבת ההנחיות (Instruction Layer): מספקת הנחיות והקשר לסוכן הקוד.

        -   זיכרון (CLAUDE.md / AGENTS.md): קובצי Markdown (CLAUDE.md
            עבור Claude Code, או AGENTS.md עבור פלטפורמות אחרות כמו
            Cursor) הנטענים להקשר של הסוכן בתחילת כל סשן. הם משמשים
            כהנחיית מערכת (system prompt) וכוללים הנחיות כלליות, מידע על
            הפרויקט והפניות לתיעוד רלוונטי נוסף. קיימת היררכיית טעינה
            (רמת משתמש, רמת פרויקט, רמת תת-תיקייה), כאשר הרמה העמוקה
            ביותר גוברת. חשוב מאוד לשמור על קבצים אלה תמציתיים כדי
            להימנע מ"ריקבון הקשר" (context rot).
        -   סגנונות פלט (Output Styles): יכולת חדשה יחסית המאפשרת
            למשתמשים להתאים אישית את פורמט הפלט של הסוכן (למשל תמציתי,
            יוזם, מסביר, או אפילו מבוסס תרשימים כמו תרשימי Mermaid). הדבר
            משפר את הקריאות וההבנה של תשובות הסוכן.
        -   כללים (Rules): הנחיות ספציפיות המוגדרות בקובצי Markdown
            בתוך התיקייה .claude/rules/. ניתן להחיל כללים באופן גורף
            (AlwaysApply), על סוגי קבצים או נתיבים מסוימים (globs), או
            בעת הפעלה מפורשת. הם משמשים לאכיפת תקני קוד, שיטות עבודה
            מומלצות והתנהגויות דטרמיניסטיות אחרות.

    -   שכבת ההרחבות (Extension Layer): מרחיבה את היכולות הבסיסיות של
        ה-Harness.

        -   Hooks (ווים): נקודות התערבות דטרמיניסטיות במחזור החיים של
            הסוכן (למשל: תחילת סשן, לפני שימוש בכלי, אחרי שימוש בכלי,
            שינוי קובץ, סיום סשן). Hooks מוגדרים בקובץ settings.json
            ויכולים להריץ סקריפטים, לבצע פקודות, או אפילו לעצור את תהליך
            הסוכן אם תנאים מסוימים אינם מתקיימים. הם מעניקים רמת שליטה
            גבוהה ומשמשים לאימות, לאכיפה ולאינטגרציה.
        -   Skills (מיומנויות): הנחיות (prompts) תבניתיות לשימוש חוזר,
            השמורות כקובצי Markdown (למשל SKILL.md בתוך תיקיית skill
            ייעודית). Skills עוטפים משימות מורכבות ורב-שלביות או
            פונקציונליות ספציפית. הם נטענים באופן הדרגתי: בתחילה רק השם
            והתיאור נמצאים בהקשר, והתוכן המלא נטען רק בעת ההפעלה (באופן
            מפורש באמצעות /skill-name, או באופן מרומז כאשר הסוכן מזהה את
            כוונת המשתמש מתוך התיאור). ניתן להגדיר ל-Skills הגבלות (למשל
            AllowedTools, DisableModelInvocation) כדי לשלוט בהיקף פעולתם
            ולמנוע פעולות לא רצויות.
        -   MCP (Model Context Protocol): פרוטוקול תקשורת סטנדרטי
            (JSON-RPC על גבי HTTP/S) שנועד לאפשר לסוכני קוד לתקשר עם
            שירותים, כלים וממשקי API חיצוניים. שרתי MCP חושפים
            פונקציונליות ספציפית (כלים, משאבים, הנחיות) שהסוכנים יכולים
            לגשת אליה, ובכך מפשטים אינטגרציות ומסתירים את המורכבות של
            ממשקי API שונים. הדבר חיוני כדי לאפשר לסוכנים לבצע פעולות
            בעולם האמיתי (למשל עבודה מול מסד נתונים, הרצת בדיקות דפדפן
            באמצעות Playwright, או גישה ל-Jira).

2.  אופטימיזציית עלויות (ניהול צריכת טוקנים):

    -   עלויות טוקנים: סוכני AI צוברים עלויות לפי טוקני קלט וטוקני פלט,
        כאשר טוקני הפלט יקרים בדרך כלל באופן משמעותי, בשל משאבי המחשוב
        הנדרשים להפקה ולהסקה.
    -   אסטרטגיות:
        -   Prompt Caching (שמירת הנחיות במטמון): מפחית את עלות טוקני
            הקלט על ידי שמירה במטמון של חלקים חוזרים בשיחה.
        -   ניהול הקשר: ניקוי (/clear) או דחיסה (/compact) של היסטוריית
            השיחה באופן קבוע, כדי למנוע "ריקבון הקשר" ולהפחית את צריכת
            הטוקנים. פתיחת סשנים חדשים עבור משימות שונות.
        -   בחירת מודל/מאמץ: שימוש במודלים פחות חזקים/יקרים או ברמות
            "מאמץ חשיבה" נמוכות יותר עבור משימות פשוטות.
        -   אופטימיזציית כלים: צמצום מספר הכלים הנטענים, או שימוש בכלים
            ייעודיים כמו RTK (Rust Token Killer) או Kaimen לסינון מידע
            לא רלוונטי מההקשר.
        -   תת-סוכנים (Sub-Agents): האצלת משימות ספציפיות לתת-סוכנים,
            המנהלים הקשר משלהם, וכך שומרים על הקשר רזה אצל הסוכן הראשי.

3.  בדיקות ואימות:

    -   האתגר: כאשר סוכני קוד מייצרים גם את הקוד וגם את הבדיקות, הם
        עלולים להפיק בדיקות "ירוקות" שאינן מאמתות בפועל את הדרישות,
        מכיוון שהבדיקות מותאמות לקוד שנוצר (שעשוי להיות שגוי).
    -   פתרונות:
        -   אימות בלתי תלוי: שימוש בכלים ניטרליים, ב-Hooks או בסוכנים
            נפרדים כדי לבחון את התוצר מול המפרט והדרישות המקוריים, במקום
            להסתמך רק על הבדיקות שהסוכן ייצר בעצמו.
        -   לולאות משוב (Feedback Loops): הטמעת מנגנונים (למשל שימוש
            ב-Playwright לבדיקות ממשק משתמש מקצה לקצה, או כלים ייעודיים
            כמו "Baby Sitter") המספקים הוכחה מוחשית להצלחה (למשל צילומי
            מסך התואמים לעיצוב, או הרצות בדיקה מוצלחות מול קריטריונים
            בלתי תלויים לאימות).
        -   אכיפה דטרמיניסטית: שימוש ב-Hooks לאכיפת תקני קוד או בדיקות
            אבטחה לפני ביצוע commit לקוד.

השיעור הבא: השיעור הבא יעמיק ב"תזמור" (Orchestration) וב"מתודולוגיות",
ויעסוק בנושאים כמו תת-סוכנים, עבודה במקביל וניהול תהליכי עבודה מתקדם, עם
דגש חזק יותר על תרגול מעשי.
